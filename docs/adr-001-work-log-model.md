# ADR-001：工作紀錄模型與翻譯維護路線

日期：2026-09-09。狀態：提案／待決策，未部署。

後續決策：使用者明確同意 B 先驗證模型、通過後再決定 C。已建立 [本地 Docker 模型原型](docker-model-poc.md)，本決策授權獨立 Custom DocType PoC，不代表授權 Custom App、原站部署或正式上線。以下候選比較保留為決策依據。

## 問題

原生 Timesheet 已證實可留空 Project/Task 保存本人工作，但用戶的核心是工作成果、數量、單位與投入工時。數量兩欄只能補資料，不能消除時間區間、修訂流程、主管範圍與每日操作成本。

## 候選比較

| 面向 | Timesheet＋設定／少量欄位 | Daily Work Log 主表＋明細 |
|---|---|---|
| 已有基礎 | 本機已驗證單列保存 | 尚未建立，不能標 PASS |
| 投入工時 | 原生需時間資訊；不得捏造起訖時間 | 可設計 work_date＋hours，需新驗證規則 |
| 成果資料 | 增加數量、單位；Result 語意需確認 | 專門設計分類、內容、數量、單位、結果、備註 |
| 審核 | 須 Workflow 配合 docstatus | 可專門設計；仍須狀態與權限實測 |
| 唯一性／直屬權限 | 不能假設原生已滿足 | 不能假設自訂 DocType 自動滿足 |
| 維護 | 延續標準 controller，需確認不衝突 | 自己維護資料模型、測試與部署方式 |
| 授權 | 目前欄位／Workflow 仍僅提案 | 新 DocType／App 須明確範圍決策；App 仍禁止 |

## 建議與決策門檻

將 Daily Work Log 列為主要候選，Timesheet 留為比較基準；暫停以「先加兩欄」作預設下一步。若「只知道投入小時也能如實登錄」是硬需求，則優先選獨立模型。若真實起訖時間可接受，且同單補正、權限、操作成本均可達標，Timesheet 仍可保留。

不採報告的任意欄位數／script 數作硬性技術上限，不把尚未實作的欄位數當現況。評估依據是需求符合度、維護負擔與驗收證據。

選定模型不等於選定部署包：Custom DocType 與 Custom App 是不同決策。若伺服器權限／併發唯一性需要程式，先提出實作與測試方案；不以 Client Script 隱藏資料替代安全檢查，不把權限延到真實員工試辦之後。

## 共同狀態原則

草稿 → 待審 → 已核准；待審可退回補正，再送審。一般補正不新增單號，工作结果與審核狀態分開。若採可提交單據：草稿／待審／退回維持 docstatus 0，核准才為 1；待審鎖定須另外執行。核准後更正才 Cancel/Amend，取消版本不計正式數據。此映射仍須依選定模型實測。

## 翻譯路線

先用 Git 翻譯清單＋受控 Data Import／Translation 維護，核對現有紀錄與匯入結果。每筆保留 language、source_text、context、translated_text；自然識別組合為語言＋原文＋context，hash ID 另作站台更新對照，不混作跨站識別。

優先處理工作紀錄、主管入口、狀態及常用提示；保留變數、HTML 與 context。Context 只有呼叫端使用相同 context 才有作用，不能只填 context 就假設隔離成功。不得以翻譯將 Cancel 偽裝成退回。

自動同步、專用翻譯 App／CSV 等保留為後續方案，不是目前先決条件。若未來建立同步程式，須有 dry-run、重複執行不新增重複紀錄、衝突檢查與受管理範圍的回復；不得刪除所有清單外人工紀錄。
