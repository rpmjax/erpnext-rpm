更新：2026-09-09。此清單與 ADR-001、下一輪驗收取代直接往 Timesheet 加欄位的單一路線；歷史實測結論仍保留。狀態不是完成宣告。

## 來源與證據

使用者提供《deep-research-工作紀錄.md》與《deep-research-翻譯問題.md》作為需求及問題研究依據。報告內 PASS、範例程式、時程、Custom App 建議屬研究判斷，不是站台驗收結果或部署授權。報告引用標記並非本 repo 可解析來源；落地前須重新核對關鍵能力與實際版本。原始報告不直接複製進公開 repo，避免夾帶環境或個人資訊。

證據分類：實測＝本輪操作／讀取已確認；回報＝使用者提供、未獨立覆核；研究＝報告提出的推論；待決策＝尚未確認規則。

## 決策責任與界線

業務負責人確認欄位、計量、審核與歷史資料可見性；技術負責人提供模型差異、權限證據及回復方案；管理員確認站台與授權變更；試辦員工／主管驗證日常使用。

財務、庫存、出勤、薪資與既有 ERP 整合不納入本輪。管理層全公司可見、另建分類主檔、獨立 App 等研究延伸項目，不自動列為已同意需求。

## 2026-09-14 新增介面待辦

- [ ] **UI-01：工作列明細內的物料按鈕前移**
  - 來源：使用者兩則截圖註記，明確要求只列待辦，本次不實作。
  - 將「搜尋物料」（search_item）與「解除物料關聯」（clear_item）從備註下方移到明細上方，與關聯物料／品名等資訊欄位放在同區域。
  - 範圍：截圖中的「編輯行」明細視窗；保留主表單已有的物料操作入口與 AJAX 候選功能，不搬動資料、不改權限。
  - 驗收：展開工作列後，物料資訊與兩個按鈕集中排列，不需越過大型備註欄才找到；搜尋與解除仍只影響當前列，待審／核准鎖定照舊。由使用者手動確認。

- [ ] **WF-02：列表批次送審**
  - 來源：使用者列表截圖要求「也規劃批次操作：+送審」；本次僅記錄規劃，未實作。
  - 入口：RPM Daily Work Log 列表勾選多筆後，右上「操作」加入「送審」。僅處理明確勾選的紀錄，不自動延伸到篩選結果或其他分頁。
  - 確認：送出前顯示選取筆數及確認提示。
  - 伺服器逐筆沿用既有送審授權、資料規則、有效主管、狀態與版本檢查；限本人草稿或退回修改。待審／已核准不得重送，不能利用批次擴權。
  - 預定策略：每筆獨立處理；合法者送審，失敗者維持原狀。明確回報成功／略過／失敗數與各筆編號、原因；未授權紀錄不透露內容。技術實作須確保單筆失敗不殘留狀態或事件。
  - 防重：重複點擊、過期版本與重試不產生重複送審事件；完成後更新列表。
  - 驗收：混合合法草稿、退回單、待審／核准單、資料不合法及無權紀錄；逐筆核對狀態、歷程、結果訊息。人工操作由使用者執行。
  - 範圍：只做員工批次送審，不包含主管批次核准或退回；批次數量上限於實作時依負載設定並明示。

- [ ] **UI-02：單筆送審按鈕移至頁首可見動作區**
  - 使用者要求評估與列待辦，尚未實作。現有頁面 API 提供 set_secondary_action，可評估將送審設為保存旁的次要動作，保留保存為主要動作，不需修改 Core。
  - 本人已保存的 Draft／Returned 才可送審；新單或有未保存修改時提示先保存，不默默合併保存與送審。Pending Review／Approved 不顯示可送審動作。
  - 沿用現有確認、權限與版本檢查；驗收包含 840px 窄視窗、保存後刷新及狀態切換，避免按鈕被工具列重繪覆蓋或再次折入選單。

- [ ] **CH-01：主管圖表視圖（初步提案）**
  - 使用者詢問規劃與原生可行性，本次記錄提案，未授權直接部署圖表。
  - 現況只有主管明細查阅，尚無已完成的圖表。當前 Dashboard Chart 原生具備 Count／Sum／Average／Group By／Custom／Report 與 Line／Bar／Pie／Donut 等類型。
  - 建議第一版：每日總工時趨勢、各直屬員工工時、審核狀態筆數。狀態須明示，避免把待審與核准資料混成已確認工時；預設範圍與是否只計核准待決策。
  - 採原生圖表呈現配 App 授權彙總（Custom Chart Source 或 Script Report），每次依登入者與當下 Reports To 篩選；不擴大原始工作單 read/report 權限。共享快取必須考慮 User 與組織關聯變更。
  - 不直接以目前最多 300 張的明細結果做完整統計，另做服務端完整聚合與數據範圍標示。子表分類工時需明細聚合，避免 join 導致主表總工時重複加總。
  - 單位與計量定義尚停用，第一版不跨物料彙總完成數量，不製作產能／效率排行榜。空白日期不視為缺勤；缺填判定需另有應填日與人員規則。
  - 驗收：圖表與明細同範圍數據一致，未授權使用者不能取得資料，不同主管／調整直屬後無快取洩漏，超过 300 張仍正確。
