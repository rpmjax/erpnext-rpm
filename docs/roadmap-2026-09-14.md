## 本批實作

**UI-01**：工作列明細順序為作業類型 → 關聯物料 → 選取時品名 → 搜尋／解除關聯 → 數量／結果／工時／備註。主表 AJAX 與物料操作入口保留。

**UI-02**：單筆已保存 Draft／Returned 的送審使用頁首 secondary action，保存仍為 primary action；新單不顯示送審，有未保存修改時要求先保存，待審／核准移除送審。不變更原權限及確認流程。

**WF-02**：列表勾選後「操作 → 送審」，一次 1–50 筆，確認筆數後呼叫 POST API。只處理選取紀錄，不延伸其他分頁。逐筆原有權限／有效主管／資料／版本檢查，重複選取與已待審核准略過。每筆使用 savepoint，預期的單筆失敗回滾，其他合法單继续；回報編號與成功／略過／失敗原因。成功項目在整個請求正常結束時提交；若未預期系統錯誤導致整個請求失敗，該請求全部回滾，請刷新確認後重試。固定按編號鎖定，降低交錯批次鎖定風險；未進行大量併發壓測。

回歸測試包含混合合法、待審、錯誤工時、過期版本、他人資料與重複選取；無失敗單事件殘留，重試不重複送審。單筆退回／重送／核准流程 PASS。測試最後 rollback，不留測試單。站台 metadata 確認新欄位排序、頁首按鈕與列表 script 載入；登入頁 200。

## 手動驗收

1. 保存未完成輸入後重新載入。展開工作列：物料資訊与搜尋／解除按鈕應集中在數量及備註之前。
2. 開一張已保存草稿：頁首保存旁應見送審；修改尚未保存時，點送審應要求先保存。窄視窗也需驗證按鈕可見。
3. 列表勾選兩張本人合法草稿 → 操作 → 送審 → 確認筆數，應回報成功並更新待審。
4. 再勾選已待審紀錄，送審應略過，不新增審核事件。
5. 主管查詢並退回一筆，員工修正保存後可用同一流程重送；歷程與編號維持一致。

## CH-01 修正後規格

目標是可設定報表，不是把三張圖寫死。三張初始範例：每日工時、各員工工時、審核狀態分布。

- 授權管理者設定分組、統計欄位／方式、篩選、排序、圖表類型及顯示名稱。
- 欄位目錄從 Work Log metadata 取得候選，經允許清單與型態檢查開放；停用／敏感欄位不自動開放。
- 主表与子表明確區分資料粒度，禁止展開子表後重複加總主表 total_hours；選擇不相容的欄位組合時提示。
- 原生圖表呈現搭配 App 授權彙總；權限固定於 session 與當下直屬範圍，報表設定不能擴權。
- 不依 300 張明細頁截斷做統計，使用完整服務端聚合，明示日期與審核狀態範圍。
- 改名／刪除／停用欄位後，設定失效要提示與禁止誤算，不悄悄替换欄位。新增欄位與跨文件公式需驗證後開放，不假設所有改動都免開發。
- 先不做無單位數量彙總、效率排名或缺勤推論。預設狀態與開放哪些欄位在該批實作前具體化。
