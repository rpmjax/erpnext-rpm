# 每日工作紀錄 MVP 規格

狀態：待實機驗證的產品提案，尚未實作。

最新實作路線待 [ADR-001](adr-001-work-log-model.md) 決策；必須先確認是否僅輸入投入工時、計量與主管規則，再選 Timesheet 或獨立模型。詳見 [需求清單](requirements-backlog.md)。

2026-09-09 補充：明細需支援完成數量與單位，正常退回補正應保留同一張單，核准後更正才使用取消／修訂。欄位、Workflow 及權限均尚未部署，最新規則與驗收見 [PoC 修正計畫](work-log-poc-plan-2026-09-09.md)。

## 使用流程

員工進入「我的工作」，開啟今日紀錄，逐列填寫工作，儲存草稿後送審。主管從「待審核」開啟整張日報，核准或附原因退回。員工可修改退回的內容後重新送審。

入口建議：今日工作紀錄、我的本週紀錄、待修改、我的工時統計；主管另有待審核與團隊統計。

## 欄位

| 層級 | 欄位 | 規則 |
|---|---|---|
| 主表 | 工作日期 | 預設公司時區的今日；可補填歷史日期 |
| 主表 | 填寫人 | 從登入帳號取得，員工不可冒用他人 |
| 主表 | 部門、審核主管 | 從受控的人員設定取得；送審時保留快照 |
| 主表 | 狀態 | 草稿、待審核、已退回、已核准 |
| 主表 | 總工時 | 由伺服器加總明細，不接受客戶端指定值 |
| 主表 | 審核紀錄 | 每次送審、核准、退回的時間、操作人與意見 |
| 明細 | 分類 | 受控選項；初始分類待部門確認 |
| 明細 | 工作事項 | 送審必填 |
| 明細 | 結果／進度 | 送審必填 |
| 明細 | 工時 | 有限正數，最多兩位小數，以小時計 |
| 明細 | 目的、對象、阻礙、下一步 | 選填，收合於詳細資訊 |
| 明細 | Project、Task | 選填；填 Task 時檢查其 Project 關聯 |

草稿允許未填完的工作列；送審至少一列完整工作。當日總工時不得超過 24 小時，不強制湊滿 8 小時。以「填寫人＋日期」限制一張有效日報，並在資料庫層處理同時建立造成的重複。

## 狀態及權限

| 目前狀態 | 操作 | 操作者 | 新狀態 |
|---|---|---|---|
| 草稿 | 儲存、增刪工作列 | 本人 | 草稿 |
| 草稿／已退回 | 送審 | 本人 | 待審核 |
| 待審核 | 核准 | 指定主管，且非本人 | 已核准 |
| 待審核 | 退回並填原因 | 指定主管，且非本人 | 已退回 |
| 已退回 | 修改 | 本人 | 已退回 |

待審核及已核准的工作內容鎖定。第一版不提供核准後直接修改；更正流程另行定義。尚未指派主管或主管停用時，阻止送審並提示管理員處理；主管自己的日報需另一位審核人。

員工只可讀取自己的日報；主管只可讀取指派給自己的送審紀錄。系統管理員維護人員、部門與主管設定，其管理操作保留紀錄。主管調動後的舊單轉派須明確處理，不自動改寫歷史快照。

以上限制需由伺服器端執行，涵蓋表單、清單、直接網址、API、報表與匯出，不能只隱藏按鈕。部門主管角色本身不代表可以讀取全公司資料。

## 統計及使用體驗

提供日期區間、人員、部門、分類與狀態篩選。核准工時預設僅計已核准日報；草稿與待審核分開顯示。明細分類統計加總明細工時，避免將整張總時數重複計算。

桌面以表格快速新增、刪除與鍵盤移動；手機至少能完成新增、編輯、儲存與送審，詳細欄位可展開。使用繁體中文標籤與易懂的欄位錯誤訊息。離開未儲存內容時提醒，伺服器儲存成功後才顯示已儲存。

試辦目標：一般員工熟悉後，可在三分鐘內完成五筆已有內容的工作紀錄；此為待驗收的目標，非已達成結果。
